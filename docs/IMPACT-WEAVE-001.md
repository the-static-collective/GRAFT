# IMPACT-WEAVE-001 — The Right Hands / four doors, one table

**Status 2026-10-26:** experimental, source-controlled **hypothetical stewardship-role** weave on an independent GRAFT branch. A local printable packet is implemented. There is NO publicly deployed service, contact, sign-up, live partner support, verified need, real-life delivery, or actual volunteer assignment behind this branch.

> **Maximum impact isn't maximum centralization.** Make the next useful act easy to discover, optional to perform, cheap to verify, and safe to refuse — across independent community rooms.

These are **roles and possibilities**, not endorsements. In particular: Coalition, churches, Waseca grocery organizers, Harmony Park contacts, any festival, campus, food shelf, artist, or survivor does not become a partner, steward, or available volunteer merely because we can imagine a crossing. A contact or relationship is NOT permission.

## What the working cross actually does

1. Operator selects **2–4 generic lanes** by enum. No person name, contact, location, private need, survivor history, case ID, real organization, exact time, or beneficiary identifier is even accepted by the schema.
2. Native pure module computes **at most 6 pairs** of hypothetical overlapping capabilities. Each pair explicitly says source and receiving steward permission **not obtained**.
3. The CLI writes a **private new local directory** with `impact-weave.json`, printable `right-hands.html`, and `graft-native-four-cards.html` rendered by the existing ORIGINAL GRAFT `printableHtml()` NECESSARY work-kit method. The native four-card draft contains no made-up public research or sources.
4. A SHA-256 receipt covers the emitted files. The filesystem output is real; outreach, publishing, work, partnership, hosting, authority, and independent confirmations are NOT performed.
5. A human may examine and decline any candidate; there is no automated following chain. If accepted, any actual community-specific action belongs to its own consenting human stewards and their separate trusted systems.

```bash

```

**Never post the private output folder without separate review and permission.** Even though this v0 currently contains only fictional roles, the private directory makes the no-publication habit explicit. This is a *question generator*, not a service directory or enrollment portal.

## A viable seven-day impact attempt (separate from code CI)

The fastest useful experiment is **not** onboarding all the fields at once.

**Days 1–2:** perform BananaSpork's backend [FIELD-001](https://github.com/the-static-collective/BananaSpork/blob/feat/campfire-selfhost-backend-001/campfire-backend/FIELD-001.md) independent-account, permission, restart and recovery checks with fictional records. Do not accept sensitive field cases until security and operations are independently validated.

**Days 3–4:** two willing adult stewards may look at this fictional Right Hands packet. Ask exactly one practical, generic question at the intersection of their actual capacities. Refusal or no response is a valid end.

**Days 5–6:** if each approves, privately plan one bounded, non-sensitive task (for example, prepare a public-safe food-resource poster or check phone readability of a public participation page). Real help involves its own actual beneficiary consent and independent outcome confirmation. Do not use a practice role card as evidence of a physical service.

**Day 7:** return with `attempted / declined / pending / privately confirmed` and the source owner's approved minimal non-identifying learning. Preserve unresolved failures. A happy story is not a receipt, and failure is not deletion.

**What counts:** one useful *verified* human result, and a reproducible safe path to another. **What does not count:** number of theoretical edges, clicks, printed cards, people who might know someone, scores, platform impressions, or assumed partnerships.

## Big horizon — scale the permission protocol, not the private database

The community can ultimately have thousands of independent **Campfires** linked by nothing more invasive than consented, separately owned public-safe opportunities. Each can run its own need/offer ledger and keep its own human relationships. JAR;VIS can prepare possible work, GRAFT can produce source-bound packets, the Garden/Abundent can host an optional public doorway, and Jubilee can retain independently witnessed acts. **No donor system becomes the authority for another merely by crossing.**

The next real high-leverage module is a **one-way, human-redacted source-safe handoff** with a reviewed scope and recipient-approved exposure. It should have a formal "no publication, no personal details, no automatic dispatch" policy and independent hostile-input tests. No such live adapter is claimed here.
